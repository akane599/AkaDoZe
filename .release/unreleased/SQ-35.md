## SQ-35

- Switching to Shizuku now survives rotation while the Shizuku prompt is open. When AkaDoZe comes back to the front and Shizuku still has no permission, it goes back to the previous mode and says why. It also goes back if Shizuku stops during the wait. Only Shizuku's own state can complete the switch, so a leftover root state no longer counts as "granted".
- Switching to Root now waits for the root check. If root isn't granted, AkaDoZe goes back to the previous mode and says why.
- The access card and the Monitor no longer show "Restore pending" right after the screen turns on while the normal restore is still running. Only entries that a restore attempt already failed on, or a damaged record, count as pending.
- The "Sensors/Doze may still be restricted" notification appears once per problem instead of on every app open or safety check. It isn't posted while the main screen or the Monitor already shows the problem, and it can appear again once the problem has cleared and comes back.
- AkaDoZe no longer starts its Doze engine (and the root check) on every process start. It starts only when something needs it, so the notification listener, tiles, alarms and app updates don't trigger a root request.
- Notices are no longer reported as shown when the tips notification channel is turned off. The music whitelist setting checks the notification-access grant itself, not whether the listener happens to be connected. If notification permission is denied for good, the summary setting offers to open the app's notification settings. The grant-helper progress dialog now closes with its screen.
- Monitor: coverage percentages never round up (Deep Doze 99.6% shows 99%), and unknown time below 1% shows as "<1%". Self-test raw output shows the first 200 lines per command and is prepared off the main thread. Self-tests can run only while the AkaDoZe service is running, with a note explaining why. While a test runs, its own record isn't shown as pending restore, and Restore and Refresh wait for it to finish. The screen-on summary appears only after a session in which at least one step actually ran. Malformed launch extras from other apps are ignored.
